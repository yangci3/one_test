# 阶段 P1.5：场景权限分层（网络管理员 / 网络用户）

**日期：** 2026-08-06  
**状态：** 设计已确认；待写实现计划  
**路线图：** `docs/superpowers/specs/2026-07-31-factory-scene-network-roadmap.md`  
**依赖：** 阶段 P1（后端模拟探测）；阶段 B2′（`scene_device`）  
**关联：** 后续 P2（历史落库 + 监控设置按用户落库）

## 1. 目标

将「三维地图 / 网络监控」从全体登录用户可见，改为按角色授权：

- **网络管理员**（及超级管理员）：完整监控能力  
- **网络用户**：仅静态三维场景 + 拓扑只读  
- **均未授权**：侧栏无三维相关入口，且不因误调接口反复弹出「当前操作没有权限」

**落地策略：方案 1（动态菜单 + 预置角色）**

- 从 `constantRoutes` 移除 `/cesium` 整段，改为 `sys_menu` 动态路由  
- SQL 预置完整菜单权限树 + 两个角色模板 `net_admin` / `net_viewer`  
- 前端按权限显隐按钮与监控运行时；无权限不发起对应请求  

**出口标准**

1. 仅挂 `net_viewer`：菜单仅「三维场景」「网络拓扑」；场景静态；无在线/离线展示；无 403 连环弹窗  
2. 挂 `net_admin`：设备管理、监控设置、监控历史、启停监控、告警等完整可用  
3. 两角色都不挂：无「三维地图」目录  
4. 在角色管理勾选/取消菜单后，用户重新登录权限变化正确  
5. 超级管理员 `admin` 行为与现网一致（全权限）

**不做（本阶段）**

- 探测历史 / 监控设置 MySQL（P2）  
- 真 ICMP ping（P4）、换厂区 tiles（P3）  
- 全局吞掉所有业务模块的 403 提示  
- 改动系统管理以外的其它默认「普通角色」菜单包（仅新增网络相关角色与菜单）

## 2. 决策摘要

| 项 | 选择 |
| --- | --- |
| 实现方式 | 动态菜单 + 预置角色 + 可勾选权限树（选项 C） |
| 网络用户范围 | 三维场景 + 网络拓扑只读（选项 B） |
| 网络用户场景形态 | **静态**：无状态轮询、无着色、无在线字段、无告警 |
| 网络管理员 | 现有监控闭环全部能力 |
| 设置存储（P2 预告） | 按登录用户各存一份（已拍板，本阶段不实现） |
| 403 策略 | 治本：无权限不调接口；不全局屏蔽 403 |

## 3. 角色

| 角色名 | roleKey | 说明 |
| --- | --- | --- |
| 超级管理员 | `admin` | 已有；保持全权限 |
| 网络管理员 | `net_admin` | 预置；挂全部三维/监控菜单与按钮权限 |
| 网络用户 | `net_viewer` | 预置；仅场景 + 拓扑只读相关权限 |

用法：

- 用户管理 → 分配角色：勾选 `net_admin` 或 `net_viewer`（可与其它业务角色并存）  
- 或角色管理 → 自建角色 → 在菜单树中勾选「三维地图」下节点（细粒度）  
- 变更后需重新登录生效（若依既有机制）

## 5. 前端行为

### 5.1 路由

- 删除 `ruoyi-ui/src/router/index.js` 中 `constantRoutes` 的 `/cesium` 块  
- 由 `getRouters` → `GenerateRoutes` 按用户菜单动态挂载  

### 5.2 三维场景（`Index.vue`）

**无 `scene:probe:query`（网络用户）**

- 不调用 `bootstrapGlobalMonitor` / 不轮询 probe  
- 不聚合建筑在线状态着色（保持默认静态外观）  
- 侧栏隐藏：全部/单设备监控开关、告警静音、监控详情等  
- 设备信息展示：名称、IP、MAC、类型、所属建筑等；**不展示在线/离线**  
- 允许：点选建筑、查看设备信息、地图基础交互（飞回中心等只读操作）  
- 链路高亮若依赖拓扑只读数据可保留；不依赖 probe 状态  

**有 `scene:probe:query`（网络管理员 / admin）**

- 保持 P1 现有动态监控行为  

### 5.3 全局监控启动点

- `main.js` 中无条件 `bootstrapGlobalMonitor()` 改为：仅当当前用户具备 `scene:probe:query`（或等价判断）时启动；否则不启动  
- 登出 / 401 仍停止轮询（沿用已有修复）  

### 5.4 拓扑页

- `net_viewer`：可查看图与链路详情；隐藏任何编辑/保存类控件（若存在）  
- `net_admin`：保持现有能力  

### 5.5 403 弹窗

- 根因：无权限用户仍进入写死菜单并发起 probe/device 写接口  
- 对策：无菜单 + 无按钮 + 无对应请求；**禁止**用全局忽略 403 作为主方案  

## 6. 后端

- `SceneDeviceController`：list/query 允许 `scene:device:list` / `scene:device:query`（viewer 可读）  
- 写操作保持 add/edit/remove 权限  
- `SceneProbeController`：仅 `scene:probe:query` / `scene:probe:edit`；viewer 不调用即可  
- 若依超级管理员绕过 `@PreAuthorize` 的既有行为保持不变  

## 7. SQL 交付物（实施计划细化）

单文件（建议）`sql/scene_rbac_p1_5.sql`，内容包括：

1. 清理冲突的旧场景隐藏菜单 / 错误 path（如曾占用 `cesium` 的记录）  
2. 插入「三维地图」目录及子菜单、按钮权限（F）  
3. 插入角色 `net_admin`、`net_viewer`  
4. `sys_role_menu`：两角色分别绑定对应菜单  
5. `admin`（role_id=1）绑定全部新菜单  

角色 id 选用未占用号段（实施时查库确认，避免与 `1`/`2` 冲突）。

## 8. 测试

1. 新建用户只授 `net_viewer`：登录后仅两菜单；场景无状态、无弹窗；设备信息无在线字段  
2. 同用户改授 `net_admin`（或加角色）后重新登录：出现全菜单与监控能力  
3. 去掉全部网络角色：无三维目录；访问旧 URL 不可用业务页  
4. `admin` 登录：三维与监控正常  
5. 网络用户停留场景页数分钟：无 403「当前操作没有权限」循环  

## 9. 风险

| 风险 | 缓解 |
| --- | --- |
| 旧隐藏菜单 path 冲突 | SQL 先删冲突行；新菜单用唯一 path/name |
| 仅改前端藏按钮仍调 API | 与权限字对齐，启动监控前检查 `scene:probe:query` |
| 已登录用户菜单缓存 | 文档写明需重新登录 |
| constantRoutes 残留 | Code review 确认 `/cesium` 已移除 |
